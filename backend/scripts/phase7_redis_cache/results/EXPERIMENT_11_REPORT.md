## 🔍 Root Cause Analysis

### 1. HikariCP Connection Pool Exhaustion

**증상**:
- Active Connections: **100/100 (100% 사용)**
- Pending Connections: **95~102** (대기 중)

**원인**:
- 고부하 상황에서 Connection Pool 크기(100) 부족
- GET /{portfolioId} 요청이 Connection을 획득하지 못하고 타임아웃

**해결 방안**:
1. ✅ **Connection Pool 크기 증가**: 100 → 150~200
2. ✅ **Connection Timeout 조정**: 현재 30s → 10s (빠른 실패)
3. ✅ **Query 최적화**: N+1 문제 재확인 (EntityGraph)

---

### 2. Redis Cache 미적용 가능성

**의심 포인트**:
- Portfolio 목록 조회 응답 시간: **~670ms** (너무 느림)
- 예상 응답 시간 (Cache Hit): **< 10ms**

**확인 필요**:
1. Redis 캐시가 실제로 동작하는가?
2. Cache Key가 올바르게 생성되는가?
3. @Cacheable 애노테이션이 작동하는가?

**검증 방법**:
```bash
# Redis 키 확인
redis-cli KEYS "sentinel:portfolios::*"

# 캐시 히트 로그 확인
grep "Cache hit" backend.log
```

---

### 3. Portfolio GET /{portfolioId} 500 Error

**가능한 원인**:
1. **DB Connection Timeout**: Pool exhaustion으로 인한 타임아웃
2. **Redis Serialization Error**: 캐시 저장/조회 시 직렬화 실패
3. **NullPointerException**: 캐시 미스 후 DB 조회 시 예외 발생

**로그 확인 필요**:
```bash
tail -100 backend.log | grep "ERROR"
```
